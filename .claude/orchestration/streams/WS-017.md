# WS-017 — Versioned CiteWire Community contract implementation

## Objective

Implement the independently approved WS-013 Community contract as a bounded,
versioned, backward-compatible runtime change. This stream is required, but it
is not authorized to begin until its predecessors are complete and explicit
owner authorization is recorded. It does not
include Studio, a plugin, a hosted control plane, accounts, persistence,
scheduling, credential storage, publishing, or any Karaya behavior.

## Priority, status, and dependencies

- Priority: P1.
- Status: required, parked, and not authorized.
- Dependencies: WS-004 and WS-013. WS-002 is transitive through WS-013.

The dirty citewire-public-platform worktree is a preserved prototype, not a
baseline, not a partial implementation, and not a merge source.

## Exclusive ownership

- src/community/
- src/config.js
- src/core/rpc.js
- src/index.js
- Contract-specific portions of test/community.test.mjs, test/rpc.test.mjs,
  test/http.test.mjs, and test/index.test.mjs
- docs/source-registry-and-rights.md

This stream does not own package metadata, server metadata, release metadata,
apps/studio, a plugin manifest, Cloud paths, Karaya paths, or external
registry/deployment state.

## Binary definition of done

- Approved WS-013 schemas are implemented without changing news.* semantics.
- Resource and capability discovery are additive and versioned.
- Registry input is schema-validated and disabled by default.
- Every Community source is inert/disabled by default.
- Unknown or ambiguous rights resolve to hold.
- No classifier can publish or externally activate anything.
- No credential input, storage, or logging is introduced.
- Community remains stateless, read-only, provider-neutral, attribution-first,
  and non-publishing.
- No Karaya policy, credential, source configuration, editorial state, or
  Cloud tenancy crosses into Community.
- Node 18 and Node 22 verification, committed protocol tests, package-content
  review, documentation, and Cloud compatibility agree.
- Separate approval exists before merge. This stream does not tag, publish,
  submit a registry entry, or deploy.
- The parked WIP has a written disposition record rather than a merge
  shortcut.

## Checks

- Run committed Community suite plus exact news.* compatibility,
  stdio/direct-HTTP resource/capability, invalid-registry, and Node 18/22
  checks.
- Run npm pack --dry-run --json to prove Studio/plugin exclusion.
- Independently review Community/Karaya/Cloud boundary and bounded Cloud
  consumer compatibility.

## Artifact and rollback

The artifact is focused Community implementation with contract verification
record. Revert only focused implementation and preserve prior news.* behavior.
A later release needs a separate owner-approved release iteration.
