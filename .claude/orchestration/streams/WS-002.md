# WS-002 — Canonical identity and authority decisions

## Objective

Resolve the owner-controlled identity model for an open-source Citewire while
preserving `MeekPhills/citewire` as the known legacy Community candidate until
an explicitly approved transition exists.

## Status

**Blocked on owner decisions.** Planning and evidence collection are allowed;
repository creation, renaming, transfer, visibility changes, package identity,
and legacy disposition are not authorized.

## Provenance

- `$launch-citewire-open-source` command described in the Citewire handoff
- Community candidate: `10aee95ac95bb437b4607723cd20fa5c8f9d1879`, draft PR #1
- Landing candidate: `ff09b68ed811531eb0ca630b65daeaf06cc3304c`, draft PR #2
- Historical check: `Openly-Useful/citewire` was proposed but not visible

Trust: high for local commits and recorded owner gates; any current GitHub
organization availability is Unknown until freshly checked.

## Last-good state

`MeekPhills/citewire` is the public MIT Community candidate, remains a draft
release candidate, and is not yet the approved canonical `Openly-Useful`
repository. `citewire@0.2.0` is unpublished.

## Completed

- The open-source program command captures an owner-gated canonical-repo
  proposal, full MCP direction, Karaya custom-consumer boundary, and policy
  guardrails.
- KAR-66 was historically created to track the program.

## Remaining

- Luis decides canonical organization and repository slug.
- Luis decides whether and how the legacy `MeekPhills/citewire` history is
  retained, forked, transferred, archived, or documented.
- Luis decides package, registry, and naming continuity before any immutable
  release action.

## Contradictions and unknowns

- `Openly-Useful/citewire` being proposed does not establish that it exists,
  can be created, or should be canonical.
- A local landing site at `ff09b68` does not establish public-domain readiness.
- Ownership, organization permissions, release reviewer configuration, and
  npm trusted-publisher access are Unknown.

## Dependencies

- WS-001 orchestration evidence.
- Explicit Luis decisions for canonical identity and legacy disposition.

## Owned paths

Future owner-approved identity documents, repository metadata, and public
README links. Do not modify them until the owner decision is recorded.

## Binary definition of done

- The canonical organization/repository and legacy treatment are written in an
  owner-approved decision record.
- Fresh GitHub evidence confirms the chosen target is accessible to the owner.
- Package, registry, documentation, and migration impacts are enumerated.
- No identity mutation happens before the decision record and explicit approval.

## Artifact

An owner-approved identity decision record linked from `PROJECT_HANDOFF.md`
and KAR-66, with fresh GitHub evidence.

## Checks

- **Baseline:** read-only `gh repo view` and local remote/branch inspection.
- **Focused:** verify organization authority, candidate repository name,
  README/package links, and release-environment prerequisites.
- **Integration:** Terra confirms the identity choice does not imply unapproved
  migration, publication, or a broken Karaya destination.

## Rollback

Before any mutation, the rollback is to make no identity change. After an
approved reversible metadata draft, revert only its focused commit. A created
or transferred repository is not assumed reversible and requires an owner plan.
