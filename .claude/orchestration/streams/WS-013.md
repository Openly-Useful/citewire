# WS-013 — Versioned public MCP contract and resources

## objective

Design a backward-compatible Community MCP expansion for article discovery, source/topic metadata, inclusion explanations, health, and MCP resources. Keep Community stateless, provider-neutral, read-only, attribution-first, MIT-licensed, and independent of Karaya credentials and editorial state.

## status

PLANNED — design only; no runtime contract change is authorized.

## provenance

- Baseline: citewire release branch agent/citewire-product-launch at 10aee95ac95bb437b4607723cd20fa5c8f9d1879.
- Existing tools: news.list, news.get, news.topics, news.about.
- Existing transports: stdio and stateless HTTP.
- GitHub issue 4 verifies resources/list, resources/read, inclusion tiers, reason tags, and durable decision traces are absent.

## last-good

Community remains dependency-free, Node 18+ ESM, self-hostable, stateless, read-only, and provider-disabled by default. Existing news.* compatibility is the rollback target.

## completed

- Current platform contract, MCP implementation, and committed tests are the compatibility baseline.
- GitHub issue MeekPhills/citewire#4 and Linear KAR-68 are the future-design anchors.

## remaining

- Approve an ADR defining versioning, capability discovery, exact schemas, rights/attribution fields, and compatibility.
- Specify the committed fixtures and routine stdio/direct-HTTP smoke coverage
  that a later separately approved implementation stream must add and execute.
- Obtain independent protocol and rights review.
- Keep Karaya inclusion policy and private decision state outside Community.

## unknowns

Resource URI scheme, negotiation strategy, inclusion vocabulary, reason tags, health semantics, and trace retention/ownership are not approved.

## dependencies

WS-002 canonical identity only. This design may proceed in parallel with later
release planning and does not block the scoped Community 0.2 candidate or
Karaya's independent shadow-safety work.
